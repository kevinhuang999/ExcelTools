# 测试数据 · Sample Data

> **一句话结论**：10 个按钮各有专属测试表（「文件名列表」不需要数据），照着下面的参数表点一遍，每个按钮的预期结果都是可核对的确定值。

数据全部虚构：无真实公司、客户、人名、批号，样品编号与费用均为编写值。可以放心截图对外演示。

---

## 一、使用方法

1. 双击 `bin/Release/ExcelTools.xll` 装上插件（Ribbon 出现「Excel 工具」）。
2. 按下表打开对应文件，**保持提示的工作表为当前表**，按下表填参数，点按钮。
3. 对照「预期结果」逐条核对。

打开文件前建议先复制一份到临时目录 —— 拆分、排序、筛选、删除、去重都会直接保存改文件。

## 三、数据设计守则（改数据前必读）

这几个约束来自源码，破了就会报「空表」或静默少算行：

1. **表头在第 1 行，数据从第 2 行起** —— 全部工具都按行 1 表头、行 2 起数据硬编码。
2. **数据必须连续，A 列每行都要有值** —— `MyTools.GetRealRows` 遇到 A/B/D/F/H 全空的行会把总行数截断到那一行。
3. **单元格里不能出现字面量 `NULL`** —— `ClearSpecialSymbols` 会把它整段替换为空。
4. **拆分的列值必须能当工作表名** —— 不超过 31 字符，不含 `: \ / ? * [ ]`。
5. **累计去重计数的输出列要在数据区右侧之外** —— 本样本数据到 D 列，所以输出用 Z。
6. **表头列数必须等于数据列数** —— 生成脚本里有断言，少写一个表头会直接报错退出（第一版就踩过：源表 5 列数据只写了 4 个表头）。

## 四、已知遗留行为（不是数据问题）

「条件筛选」的 **SQL 查询**按钮把关键列的字母直接当 SQL 字段名用（`WHERE [A] IS NOT NULL`），而 Excel 的 OLE DB 驱动取的是第 1 行表头名作字段名。所以只有当表头字面就是 `A`/`B`/`C` 时才可能命中，常规表头上点它大概率报「找不到列」。测「筛选」按钮即可，SQL 分支要单独立项修。

## 五、重新生成

```bash
python _generate_samples.py
```

`_generate_samples.py` 是这批数据的唯一来源，改数据改脚本重跑，顺便会打印每个按钮的预期结果（可直接抄回上表核对）。只依赖 `openpyxl`。

一个坑（写进脚本注释了）：openpyxl 3.1.5 里只要读一次 `ws["A1"]`，内部游标 `_current_row` 就会被推高，之后 `ws.append()` 会把表头写到第 2 行。所以脚本一律用 `ws.cell(row=, column=)` 显式落位，不用 `append`。
